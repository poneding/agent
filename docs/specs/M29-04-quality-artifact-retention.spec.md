# M29-04 Quality Artifact Retention Spec

## Purpose

Make quality evidence artifacts stable, discoverable, and safe to upload from CI.

## Product Context

M29-02 writes reports. M29-04 standardizes artifact names, text summaries, retention notes, and failure diagnostics so reviewers can inspect failed gates quickly.

## Scope

This spec delivers:

- stable artifact filenames
- text summary artifact
- README and CI upload path alignment
- bounded diagnostic messages

Owned by other specs:

- report schema: M29-01
- CI workflow invocation: M29-03

## Architecture

Artifacts live under `target/agent-ci/` and are generated by `xtask`.

## Public Contracts

```text
target/agent-ci/quality-gate-report.json
target/agent-ci/quality-gate-summary.txt
```

## State and Failure Handling

- artifact directory is created on every run
- stale report files are overwritten atomically where practical
- failed runs still write partial evidence

## Security and Privacy

- summaries do not include raw logs
- diagnostic values are bounded and redacted

## Testing Strategy

- artifact path tests
- summary content tests
- failed run partial-report tests

## Acceptance Criteria

- CI and README reference the same artifact paths.

## Completion Signal

M29-04 is complete when artifact output is deterministic and documented.
